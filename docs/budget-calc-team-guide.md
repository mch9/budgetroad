## 0. 30초 요약 (TL;DR)

> 답변을 **두 종류**로 쓴다.
> **가치관 질문** → "당신이 어떤 신랑신부인가" = **페르소나(5종)**
> **실측 질문** → "당신의 상황" = 지역·시즌·하객·예산
>
> 그다음 **페르소나가 '스타일과 고정비'를 정하고, 실측 상황이 '식대 같은 변동비'를 정한다.**

```
14문항 답변
  ├─ 가치관 6문항(Q) ─▶ ①② 2축 점수 → 페르소나(5종)
  └─ 실측 5문항(M) ───▶ ③  지역·시즌·하객·예산·양가
                             │
       페르소나 + 실측 ──────┤
                             ▼
                 ④ 식장 종류 추천(호텔/일반홀/하우스/스몰)
                             ▼
                 ⑤ 항목별 금액 + 총액   ← 돈 계산 핵심
                             ▼
                 ⑥ 진단(예산 적정?) + ⑦ 조언(절약·투자)
```

**같은 답변 → 항상 같은 결과** (결정론적 순수 함수). 그래서 공유 링크가 결과를 100% 복원한다.

## 1. 공통 언어 (이 단어들로 대화하자)

| 용어 | 뜻 |
|---|---|
| **페르소나** | 가치관 답변으로 정해지는 결혼 유형 5종. 결과의 뼈대를 정한다. |
| **2축 점수 (a / b)** | 가치관 6문항이 누적하는 점수 (설계 문서 기준). **a축(투자 성향) = 실용·최소화(−) ↔ 격식·이벤트(+)** / **b축(우선순위) = 개인·경험·사진·연출(−) ↔ 하객·공적·식사·편의(+)**. ⚠️ **연출·사진 중시 = b 음수(−)**, **하객·식사 중시 = b 양수(+)** (경험연출이 b<0인 이유). |
| **변동 항목** | 사용자 입력(하객·지역·시즌·토글)에 **반응**해서 금액이 바뀌는 항목. |
| **고정 항목** | 페르소나로만 정해지고 입력에 **반응 안 하는** 항목 (예물·혼수·신혼여행). |
| **보증인원** | 식장 타입마다 정해진 최소 청구 인원. 실제 하객이 이보다 적어도 이 인원으로 식대를 매긴다. |
| **밴드(band)** | 페르소나별 '정상 예산 범위'. 계산 총액이 이 안/위/아래인지로 진단한다. |
| **토글** | '추가금 케어' 항목 25개. 켜고 끄면 해당 금액이 더해지거나 빠진다. |

### 페르소나 5종 (한 줄 정의)

| 페르소나 | 2축 위치 | 성향 한 줄 |
|---|---|---|
| **전통격식** | a≥0, b≥0 | 양가·격식 중시, 큰 식장·높은 예단/예물 |
| **표준실용** | a<0, b≥0 | 무난·합리, 평균적 구성 |
| **경험연출** | a≥0, b<0 | 사진·분위기 중시, 스드메/연출 투자 |
| **본질미니멀** | a<0, b<0 | 소규모·실속, 신혼생활 우선 |
| **탐색미결정** | a·b 둘 다 0 근처 | 아직 우선순위 미정 → **표준실용 값을 빌려 씀** |

## 2. 계산 파이프라인 (7단계)

### ①+② 답변 → 페르소나
- **점수에 들어가는 건 가치관 6문항(Q1·2·3·4·7·8)뿐.** 선택지마다 a·b 점수를 더한다.
- T형 3문항(취향 디테일)·M형 5문항(실측)은 **점수에 안 들어감.**
- 두 축의 부호로 사분면을 갈라 페르소나 결정 (위 표의 경계 조건).

### ③ 실측 답변 → 계산 변수
안 고르면 괄호 안이 기본값:

| 입력 | A | B(기본) | C | D |
|---|---|---|---|---|
| **예산(M1)** | 1,800 | 2,750 | 4,250 | 5,500만원 |
| **하객(M2)** | 30 | 100 | 225 | 350명 |
| **지역(M5)** | 서울 | 수도권 | 광역시 | 지방 |
| **시즌(M4)** | 성수기 | 비성수기 | – | – |
| **양가압력(M3)** | 0 당사자주도 | 1 조율형 | 2 양가압력 높음 | – |

여기에 **페르소나가 '기본 스타일'을 얹는다**: 드레스 등급, 메이크업 등급, 본식촬영(연계 80만 / 외부 150만), 토글 25개의 기본 ON/OFF.

**특수 강제 규칙(중요):**
- **양가압력 높음(M3=C)** → 폐백음식·폐백수모·주례·혼주메이크업·한복대여 **강제 ON**
- **경험연출 + 인생샷 태그(T2=A)** → 가봉스냅·퍼스트웨어 **강제 ON**

### ④ 식장 추천
페르소나 + 하객 + 예산으로 식장 형태를 추천하고 4개 타입으로 정리한다.

| 식장 타입 | 최소 보증인원 | 대관료 |
|---|---|---|
| 호텔 | 200명 | 0원 (식대에 포함) |
| 일반홀 | 200명 | 200만원 |
| 하우스 | 80명 | 300만원 ⚠️*추정값* |
| 스몰 | 30명 | 100만원 ⚠️*추정값* |

> ⚠️ **식장 타입은 사실상 페르소나가 정한다.** 전통격식·표준실용·탐색미결정은 거의 호텔/일반홀(보증 200)로 떨어진다. 하객 수가 안 먹히는 경로도 있다 (전통격식 저예산 = 하객 무관 컨벤션홀, 탐색미결정 = 무조건 일반홀 fallback).

### ⑤ 금액 계산 (핵심)
**모든 항목은 둘 중 하나다 — 이것만 기억하면 된다.**

| 부류 | 항목 | 무엇에 반응하나 |
|---|---|---|
| 🟢 **변동** | 식대 | 하객 + 지역 + 시즌 + 식장 보증인원 |
| 🟢 **변동** | 스드메 | 지역 + 시즌 + 페르소나 등급 + 켠 토글 |
| 🟢 **변동** | 추가금 토글 25개 | 켜고 끔 + 지역·시즌 |
| 🔴 **고정** | 예물·예단 | **페르소나만** |
| 🔴 **고정** | 혼수 | **페르소나만** |
| 🔴 **고정** | 신혼여행 | **페르소나만** |

**식대 공식 (가장 자주 오해하는 부분):**
```
식대 = max(내 하객, 식장 최소보증) × 1인당가
```
- 1인당가(지역·시즌별): 서울 8~9 / 수도권 7 / 광역시 6 / 지방 5만원
- **총액 = 예식장(식대+대관료+장식+본식촬영+예식장토글) + 스드메 + 예물·예단 + 혼수 + 신혼여행**

### ⑥+⑦ 진단 + 조언
- **진단**: 핵심금액(스드메+예식장, *대관료 제외*)을 페르소나 **밴드**와 비교
  - 밴드 안 → **FIT**(무난) · 위 → **OVER**(줄이세요) · 아래 → **UNDER**(여유 있어요)
  - 본질미니멀인데 큰 홀 → **WARN**(스몰/하우스로 바꾸세요) — *WARN은 본질미니멀에서만 뜬다*
- **조언**: 상태별 절약 제안(불필요 토글 끄기 · 하객 조정 · 식장 변경) + 페르소나별 **고정 투자 추천 2개**

## 3. 컨트롤 맵 — "이 결과를 바꾸려면 이 입력을 건드린다"

각 사용자 입력이 **무엇에 영향을 주는지** 역방향으로 정리. (팀 대화에서 "이게 왜 안 변하지?"를 막는 표)

| 사용자 입력 | 영향을 주는 결과 | 영향 없는 곳 |
|---|---|---|
| **가치관 6문항(Q)** | 페르소나 → 스타일·고정항목·토글기본값·밴드·식장타입 (= **결과 전반의 뼈대**) | – |
| **예산(M1)** | **식장 추천 분기에만** 영향 | ⚠️ 진단(적정/초과 판정)에는 **안 쓰임** — 진단은 페르소나 밴드 기준 |
| **하객(M2)** | 식대(`max` 바닥 위에서만), 식장 추천 분기 | 예물·혼수·신혼여행 |
| **지역(M5)** | 식대 1인당가, 스드메 베이스, 토글 가격 | 예물·혼수·신혼여행, 보증인원, 대관료 |
| **시즌(M4)** | 식대 1인당가(성수기 할증), 스드메, 토글 가격 | 고정 항목 |
| **양가압력(M3)** | 폐백·주례·혼주메이크업·한복 토글 강제 ON | 금액 직접 매핑은 없음(토글 경유) |
| **취향 태그(T)** | 경험연출+T2=A → 가봉스냅·퍼스트웨어 ON. 점수엔 미반영 | 페르소나 분류 |
| **토글 직접 ON/OFF** | 해당 항목 가산/감산 (지역·시즌 가격) | 고정 항목 |

> 💡 **꼭 알아야 할 두 가지**
> 1. **예물·혼수·신혼여행은 지역·하객·예산을 아무리 바꿔도 안 변한다.** 페르소나 평균 추정값이고, UI에도 "유형 평균 추정값이에요"라고 표시된다.
> 2. **사용자가 입력한 '목표 예산(M1)'은 적정/초과 진단에 직접 쓰이지 않는다.** 진단은 페르소나별 밴드와 비교한다. (목표 예산은 식장 추천에만 영향)

## 5. 식대 공식, 숫자로 (max의 함정)
서울·성수기 기준:

| 내 하객 | 추천 식장(보증) | 청구 인원 | 식대 |
|---|---|---|---|
| 50명 | 일반홀(200) | **200명** | **1,600만원** |
| 150명 | 일반홀(200) | **200명** | 1,600만원 |
| 250명 | 일반홀(200) | 250명 | 2,000만원 |
| 50명 | 스몰(30) | 50명 | 400만원 |

> `max()` 때문에 **호텔/일반홀을 추천받으면 하객 200명 미만은 전부 200명으로 청구된다.** "50명 미만"만이 아니라 **하객 A(30)·B(100) 선택 대부분이 해당.** → 6장 P0 참고.

## 6. 얼라인 포인트 — 함정·한계 (논의 전에 모두 알고 있어야 할 것)

1. 🔴 **[P0] 소규모인데 200명 청구**: 표준실용·전통격식·탐색미결정 페르소나에서 작은 하객 수를 골라도 식장 보증 200명에 끌려 올라간다(식대 최대 1,600만원). 본질미니멀(보증30)·경험연출(보증80)은 정상. → **배포 전 결정 필요.**
2. **예물·혼수·신혼여행 입력 무반응**: 페르소나 평균값 고정. v0 의도지만 사용자가 "내 거랑 다르다" 느낄 수 있음(UI에 명시는 됨).
3. **식장 타입을 페르소나가 정함**: 하객 수가 무시되는 경로 있음(전통격식 저예산, 탐색미결정 fallback).
4. **목표 예산이 진단에 안 쓰임**: 적정/초과 판정은 페르소나 밴드 기준. 사용자 입력 예산과 무관.
5. **탐색미결정 = 표준실용 복제**: 독립 설계가 아니라 fallback.
6. **하우스/스몰 대관료는 `[추정]`**: 코드 주석에 명시된 미검증 임시값. Phase 2 실측 대상.
7. **지역 단가표는 자동 생성물**: 손으로 고치지 말 것(4-실무 메모).
8. **첫 옵션 쏠림 가능성**: 모든 첫 선택지를 고르면 전통격식(a=2,b=3). 실제 응답 분포 모니터링 필요.

## 7. 우리가 컨트롤할 수 있는 레버 (어디를 바꾸면 무엇이 바뀌나)

> 결과를 조정하려면 아래 위치를 바꾼다. **숫자/규칙을 바꾸면 모든 사용자 결과가 즉시 영향받으니** 팀 합의 후 변경.

| 바꾸고 싶은 것 | 레버 (파일) |
|---|---|
| 예산·하객 구간 대표값 (예: 30→40) | `src/lib/onboarding-v6.ts` (M1·M2 매핑) |
| 페르소나 분류 경계 | `src/lib/onboarding-v6.ts` `classifyPersona` |
| 가치관 선택지 점수 | `src/lib/onboarding-v6.ts` (STEPS 점수) |
| 예물/혼수/신혼여행 고정값, 스타일, 밴드 | `src/lib/budget-engine/data/type-config.ts` |
| 식장 보증인원·대관료 | `src/lib/budget-engine/data/venue-profiles.ts` |
| 식장 추천 분기 규칙 | `src/lib/budget-engine/stages/stage4-venue.ts` |
| 지역·시즌 식대 단가 | CSV 갱신 후 `npm run build:pricing` (직접 편집 금지) |
| 토글 가격 | `src/lib/budget-engine/data/toggle-prices.ts` |
| 토글 기본 ON/OFF, 강제 규칙 | `toggles-meta.ts` / `stages/stage3-variables.ts` |
| 진단 임계값(OVER/UNDER/WARN) | `src/lib/budget-engine/stages/stage6-consistency.ts` |
| 진단·조언 문구, 투자 추천 | `src/lib/budget-engine/stages/stage7-advice.ts` |

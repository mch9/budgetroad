# 🤝 팀 협업 가이드 — 두 명 동시 작업

> 이 문서는 **사람**(작업 순서)과 **AI**(작업 규칙) 둘 다를 위한 가이드입니다.
> 바이브 코딩을 시작하기 전에 한 번 읽고, 작업할 때 AI에게는 [4. AI에게 줄 규칙](#4-ai에게-줄-규칙-작업-시작할-때-복붙)을 복사해서 붙여넣으세요.

---

## 1. 누가 무엇을 — "방" 나누기

같은 집을 둘이 동시에 리모델링하는 거예요. **서로 다른 방만 만지면 안 부딪힙니다.**

| | 담당 | 작업 브랜치 | ✅ 내 방 (여기만 작업) | 🚫 만지면 안 되는 곳 |
|---|---|---|---|---|
| **A** | 랜딩 페이지 | `feature/landing-page` | `src/app/page.tsx`<br>`src/components/landing/`<br>`public/landing/` | `src/components/result/`<br>`src/components/manage/`<br>`src/lib/budget-engine/` |
| **B** | 결과 이후 체크리스트·예산 관리 | `feature/manage` | `src/components/manage/` (새로 만듦)<br>`src/app/manage/` (새로 만듦) | `src/app/page.tsx`<br>`src/components/landing/` |

- **공통 출발선 = `main`** — 항상 여기서 새로 시작하고, 여기로 합칩니다.
- 위 브랜치·폴더 이름은 예시예요. 바꾸고 싶으면 둘이 합의해서 바꿔도 됩니다 (단, 정했으면 끝까지 유지).

---

## 2. 맨 처음 한 번만 (각자 컴퓨터에서)

### A님 (랜딩) — 이미 만든 작업이 있어요
랜딩은 `feature/landing-page`에 이미 작업이 있습니다. AI에게 이렇게 시키세요:
> "`feature/landing-page` 브랜치로 옮기고, `main`의 최신 내용을 합쳐서 최신 상태로 만들어줘. 충돌 나면 알려줘."

### B님 (체크리스트·예산 관리) — 새로 시작
AI에게 이렇게 시키세요:
> "`main`의 최신 내용을 받아서, 거기서 `feature/manage`라는 새 브랜치를 만들어줘."

---

## 3. 매일 작업 루틴 (이 4단계 반복)

비개발자도 AI에게 시키면 됩니다. 명령어는 참고용이에요.

| 순서 | 무엇 | AI에게 이렇게 말하기 |
|---|---|---|
| **①** | **최신 받기** (작업 시작할 때) | "작업 시작할게. `main` 최신 내용을 내 브랜치로 가져와줘." |
| **②** | **작업** (바이브 코딩) | [4번 규칙] 을 먼저 붙여넣고 → 원하는 작업 요청 |
| **③** | **올리기** (작업 끝/중간 저장) | "지금까지 작업을 커밋하고 GitHub에 올려줘(push)." |
| **④** | **합치기** (며칠에 한 번) | "내 브랜치를 `main`에 합치는 Pull Request를 Draft로 만들어줘." |

> ④의 PR은 **항상 Draft로** 만들고, **합치기(Merge)는 사장님이 GitHub에서 직접** 누르세요.

---

## 4. AI에게 줄 규칙 (작업 시작할 때 복붙)

바이브 코딩 시작할 때 **맨 처음 한 번** 아래 박스를 붙여넣으면, AI가 남의 방을 안 건드립니다.

**A님 (랜딩) 용:**
```
너는 랜딩 페이지 담당이야. 아래 폴더 안에서만 작업해:
- src/app/page.tsx
- src/components/landing/
- public/landing/
다음은 절대 수정하지 마: src/components/result/, src/components/manage/, src/lib/budget-engine/
공용 파일(package.json, prisma/schema.prisma, src/app/globals.css, src/app/layout.tsx)을
바꿔야 하면 먼저 나에게 물어봐.
```

**B님 (체크리스트·예산 관리) 용:**
```
너는 '결과 이후 체크리스트·예산 관리' 담당이야. 아래 폴더 안에서만 작업해:
- src/components/manage/ (새로 만들어도 됨)
- src/app/manage/ (새로 만들어도 됨)
다음은 절대 수정하지 마: src/app/page.tsx, src/components/landing/
기존 결과 페이지(src/components/result/)나 예산 엔진(src/lib/budget-engine/)을
참고는 하되 수정은 하지 말고, 바꿔야 하면 먼저 나에게 물어봐.
공용 파일(package.json, prisma/schema.prisma 등)도 바꾸기 전에 물어봐.
```

---

## 5. 공용 파일 — 건드리기 전 단톡에 "한마디"

이 파일들은 둘 다 건드리면 **충돌(합칠 때 git이 멈춤)** 1순위예요. 만지기 전 단톡에 "나 지금 이거 건드린다" 한마디 하세요.

- `package.json` — 라이브러리 추가/삭제할 때
- `prisma/schema.prisma` — 데이터 저장 구조 바꿀 때 (**주로 B님**. 저장 기능 만들면 여기 건드림 → B님이 도맡기)
- `src/app/globals.css` — 전역 색·폰트
- `src/app/layout.tsx` — 전체 공통 틀
- `src/components/ui/` — 공용 버튼·카드 등

---

## 5.5 AI가 "이거 바꿔도 돼요?" 물으면 — 쉬운 신호등 🚦

두 사람은 '다른 방'을 만들어서 **거의 안 부딪힙니다.** AI가 뭔가 바꿔도 되냐고 물으면, 먼저 되묻고(*"왜 필요해? 내 폴더 안에서 해결 안 돼?"*), 그래도 필요하다면 아래로 판단하세요.

| 신호 | 상황 (쉬운 말) | 대응 |
|---|---|---|
| 🟢 | 내 폴더 안에서 새로 만들기 / 새 기능에 필요한 부품 설치(`package.json`) | **"응, 해"** (부품은 "왜 필요한지 한 줄"만) |
| 🟡 | 데이터 저장 설계(`prisma`) · 결과화면(`result/`) · 계산로직(`budget-engine/`) 고치기 | **해도 되지만 단톡에 "나 이거 건드림" 공유** |
| 🛑 | 전체 색·폰트(`globals.css`) · 모든 화면 공통 틀(`layout.tsx`) · 남의 화면 폴더 | **멈추고 상대에게 먼저** (둘 다 영향) |
| ❓ | 헷갈림 | **무조건 상대에게 톡** — 그게 제일 안전, 바보 같은 질문 없음 |

> 한 문장 요약: **🟢 내 방은 맘대로 / 🛑 집 전체 공유물(색·폰트·공통틀)만 같이 정하기.**
> 랜딩(`page.tsx` + `landing/`)과 관리(`manage/`)는 파일이 달라서, B가 결과·계산을 건드려도 **A의 랜딩엔 영향이 없습니다.**

---

## 6. 며칠에 한 번 합치고, 충돌 나면

- **2~3일에 한 번**은 꼭 `main`에 합치세요(PR). 오래 따로 가면 합칠 때 충돌이 산더미가 됩니다.
- **충돌이 나면** 당황하지 말고 AI에게: "충돌 난 부분 보여주고, 양쪽 내용 비교해서 어떻게 합칠지 추천해줘." → 추천 보고 결정.
- **불안하면 합치기 전에** 물어보세요. 합치기(Merge)는 되돌리기 어려우니, Draft PR 상태에서 충분히 확인 후 사장님이 직접 누릅니다.

---

## 한 줄 요약
**각자 자기 방(폴더)만 + 자기 브랜치에서 + AI에게 규칙 박고 + 2~3일에 한 번 합치기.** 이게 전부예요.
